Server и Client Components — это классификация компонентов.
CSR, SSR, SSG и ISR — стратегии/механизмы rendering.

API — это источник данных.
SSR — это способ подготовить страницу.

🔹 CSR — Client-Side Rendering - Браузер получает данные и строит/обновляет интерфейс.

🔹 SSR - Сервер получает данные и выполняет rendering.

🔹 SSG — Static Site Generation. Страница создаётся заранее, а не при каждом запросе.

🔹 ISR — Incremental Static Regeneration. ISR похож на SSG. Но появляется обновление:
Страница может быть статической, но её данные могут периодически обновляться.


📌 CSR

При CSR:

Browser
   ↓
React
   ↓
fetch()
   ↓
API
   ↓
data
   ↓
setState()
   ↓
React re-render

Данные получает браузер.


📌 SSR

При SSR:

Browser
   ↓
Request
   ↓
Server
   ↓
fetch()
   ↓
API
   ↓
data
   ↓
Rendering
   ↓
Browser

Данные получает сервер.


🔹 Самая важная разница

CSR
Данные → браузер
Rendering → браузер

SSR
Данные → сервер
Rendering → сервер


📌 SSG — создание статической страницы заранее.
Страница может быть подготовлена во время build.
Для обновления статических данных используется revalidation.


🔑 Главное запомнить

CSR → rendering в браузере
SSR → rendering на сервере при запросе
SSG → rendering заранее



📌 ISR расшифровывается как Incremental Static Regeneration.
При ISR страница/данные могут быть подготовлены заранее.
После периода revalidate Next.js может обновить данные и регенерировать результат.
revalidate: 60 означает период в 60 секунд для revalidation.
SSG — создать статически.
ISR — создать статически + обновлять.

📌 Metadata и Client Component

В Next.js App Router Metadata можно экспортировать из page.tsx или layout.tsx.

Если файл является Client Component: "use client";
то нельзя просто использовать в этом же файле обычный экспорт:

export const metadata: Metadata = {
  title: "Products",
};

Поэтому Metadata обычно определяется в Server Component / layout.
